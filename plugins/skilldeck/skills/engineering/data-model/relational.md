# Relational shape

Read this after the project store is relational. Skip it for a document store.

- **Identity is explicit.** A primary key the domain owns, not a row number you hope stays stable. Say whether it is generated by the store or by the application, and pick the one the project already uses.
- **Relationships are constraints.** A foreign key for a relationship that must exist. An optional relationship is optional in the schema, not only in the type.
- **Uniqueness is a constraint, not a check before insert.** Two requests will pass the check together. The store is the one that can refuse the second.
- **Indexes follow lookups you have.** The key you filter or join on gets an index. An index for a query nobody runs is write cost with no reader.
- **Null means unknown, not a sentinel.** A missing amount and a zero amount are different facts. Do not overload one column for both.
- **Evolution stays expand, then migrate, then contract.** Add the new column or table while the old one still serves reads. Backfill. Switch callers. Drop the old one in a later change, with an owner. A migration that rewrites and drops in one step cannot be rolled back.

The ORM, the migration runner, and the SQL dialect come from the project. This page decides the shape, not the vendor.
